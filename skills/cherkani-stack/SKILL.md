# Cherkani Stack

Use this skill as the single entrypoint for Cherkani development work. Cherkani
Stack coordinates the best parts of CStack, GStack, and specialist engineering
skills; none becomes a competing parent router.

## Workflow

1. Start or resume a goal with an outcome, acceptance checks, risks, phase, and
   next action.
2. Run the expert lifecycle: Founder brief → CEO review → Context → Spec →
   Taste → Architecture → DX → Plan → Build → QA → Security → Adversarial
   review → Ship → Learn.
3. Read the nearest `AGENTS.md`, relevant project docs, current status, and
   session handoff before acting.
4. Apply the bundled CStack and GStack capability references plus the
   capability catalog when available. Use Graphify for navigation and existing
   project evidence, then delegate to the capability that matches the current
   phase.
5. Add specialist skills only when their capability is relevant.
6. Verify each meaningful slice and record exact evidence.
7. End every phase and command with a compact report and a situation-specific
   `Next:` action. Use the cross-platform verification matrix when relevant.

## Non-negotiables

- Follow the user's explicit approvals and project rules.
- Never push, deploy, apply remote migrations, modify production data, or write
  external tracking without current-task approval.
- Reuse existing components and dependencies before adding new ones.
- For UI work, complete the design, accessibility, theme, and browser-review
  gate described by the project's `AGENTS.md`.
- Keep external references as guidance only; do not copy proprietary assets or
  credentials.
- Do not mark a goal complete without acceptance-check and verification evidence.

When this repository is available, read its root `AGENTS.md` for the complete
contract. When installed as a standalone skill, use this workflow and the
project's own rules as the source of truth.
