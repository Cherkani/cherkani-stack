# Cherkani Stack

Use this skill as the single entrypoint for Cherkani development work. Cherkani
Stack coordinates the best parts of CStack, GStack, and specialist engineering
skills without inheriting redundant parent routing.

## Workflow

1. Start or resume a goal with an outcome, acceptance checks, risks, phase, and
   next action.
2. Run Founder brief → CEO review → Context → Spec → Taste → Architecture →
   DX → Plan → Build → QA → Security → Adversarial review → Ship → Learn.
3. Read the nearest `AGENTS.md`, project docs, current status, and session
   handoff before acting.
4. Read the curated CStack/GStack capability references and the capability
   catalog when available. Use Graphify and project evidence for navigation,
   then delegate to the matching capability using `references/integrations.md`.
5. Add specialist skills only when their capability is relevant.
6. Verify each meaningful slice and record exact evidence.
7. End every phase and command with a concise report and a situation-specific
   `Next:` action. Use the cross-platform matrix when the surface spans devices
   or runtimes.

## Non-negotiables

- Follow the user's explicit approvals and project rules.
- Never push, deploy, apply remote migrations, modify production data, or write
  external tracking without current-task approval.
- Reuse existing components and dependencies before adding new ones.
- For UI work, complete the design, accessibility, theme, and browser-review
  gate described in `AGENTS.md`.
- Keep external references as guidance only; do not copy proprietary assets or
  credentials.
- Do not complete a goal without acceptance checks and verification evidence.

When this repository is available, read its root `AGENTS.md` for the complete
contract. When installed as a standalone skill, use the project's own rules as
the source of truth.
