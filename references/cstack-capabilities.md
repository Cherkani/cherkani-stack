# CStack Knowledge — Curated

Cherkani Stack preserves these CStack behaviors as native rules:

1. Read applicable `AGENTS.md`, Git state, project configuration, docs, and
   scripts before choosing a workflow.
2. Use Graphify query/path/affected when a graph exists; narrow source reading
   before broad search.
3. Classify the task before acting: idea, architecture, implementation, bug,
   UI, database, security, QA, documentation, deployment, or release.
4. Choose the narrowest complete workflow and state the goal, checks, risks,
   and release path.
5. Default tracking is `none`; ClickUp is opt-in and external writes are
   announced and approved.
6. Respect project branch, test, security, migration, environment, and release
   rules. Never infer approval for remote or irreversible work.

This is a distilled operating contract, not a copy of CStack's runtime. The
former CStack source is archived only for migration comparison; Cherkani Stack
is now the active router.
