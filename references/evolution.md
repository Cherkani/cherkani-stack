# Stack Evolution

Only change the global stack when evidence shows a repeated problem, repeated
manual step, or broadly useful pattern.

1. Capture the evidence and affected projects.
2. Put the fix in the correct layer: policy, router, workflow, specialist
   skill, project docs, or tooling.
3. Update one canonical source.
4. Record the change in `STACK_CHANGELOG.md`.
5. Test a representative fresh session and a resume session.
6. Remove stale or duplicated guidance.

Review installed skill sources for overlap, maintenance, license, permissions,
and context cost before adding them.
