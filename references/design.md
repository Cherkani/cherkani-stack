# Design Contract

Design is a required quality phase, not optional polish. Select the smallest
relevant combination of:

- component reuse and existing project primitives;
- `frontend-design` or `frontend-ui-engineering`;
- `apple-design`, `emil-design-eng`, `design-taste-frontend`, and
  `impeccable`;
- `fixing-accessibility` and `web-design-guidelines`;
- motion, mobile, stress-testing, and browser QA skills when relevant.

Verify hierarchy, interaction, themes, responsive behavior, focus, keyboard
access, localization, long content, and RTL where applicable. Prefer clear,
state-driven composition over decorative patterns and gratuitous animation.

## Reference sources

Use Jitter, Animos, Refero Styles, Animations.dev, and Genjutsu as visual or
motion references when they clarify a decision. Use Apple Design, Emil
Kowalski, Impeccable, Taste Skill, AGI Whitelist, and Find Skills as design,
critique, technology-values, or discovery references. These sources guide
thinking only. Do not copy their assets, templates, paid services, or
proprietary code without explicit approval and license review.

## Related engineering sources

Use Ponytail for reuse-first, YAGNI implementation decisions. Use Addy
Osmani's `agent-skills` collection for frontend engineering, testing, security,
planning, simplification, and shipping practices. Use OmniRoute skills only for
OmniRoute API or CLI work; never activate provider-routing skills for unrelated
projects and never expose credentials.
